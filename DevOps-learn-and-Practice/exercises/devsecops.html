DevSecOps & CI/CD

What is shift-left security?

Answer

Integrating security activities earlier in the software delivery lifecycle — at design, commit, build, and test — rather than only at release or in production. Goal: cheaper fixes, fewer surprises, shared ownership between Dev, Sec, and Ops.

Name three security checks you would add to a CI pipeline.

Answer

Common examples: secret scanning (gitleaks), SAST (Semgrep), SCA (Trivy/npm audit), IaC scanning (checkov/tfsec), container image scanning, and policy-as-code gates (OPA/Conftest).

What is the difference between SAST and DAST?

Answer

SAST (Static Application Security Testing) analyzes source or bytecode without running the app — fast feedback in CI. DAST (Dynamic Application Security Testing) tests a running application, often from outside, finding runtime/config issues SAST misses.

What is an SBOM and why does it matter for supply chain security?

Answer

A Software Bill of Materials lists components, libraries, and dependencies in an artifact. It enables rapid CVE response, license compliance, and provenance tracking — central to SLSA and modern supply-chain programs.

What is policy-as-code in DevSecOps?

Answer

Expressing security and compliance rules as versioned, testable code (OPA/Rego, Kyverno, Sentinel, Azure Policy) evaluated automatically in CI/CD or at admission time — replacing manual checklist reviews.

Why should CI pipelines use OIDC instead of long-lived cloud keys?

Answer

OIDC federation lets GitHub Actions (or similar) obtain short-lived tokens scoped to a role — no static secrets in repos, reduced blast radius, easier rotation and audit.

What does "fail open" vs "fail closed" mean for a security gate?

Answer

Fail closed: block the pipeline when the scanner errors or finds critical issues — safer, may slow delivery. Fail open: allow on scanner failure — faster, risky. Production DevSecOps usually fail closed on critical findings after tuning false positives.

What is GitOps and how does security fit in?

Answer

GitOps uses Git as the source of truth for desired state; controllers reconcile clusters. Security fits via signed commits, PR reviews, IaC scanning on merge, admission policies, and drift detection.

What is SLSA and what problem does it address?

Answer

Supply-chain Levels for Software Artifacts — a framework for build integrity and provenance. Addresses tampered builds, dependency confusion, and untrusted artifacts in the delivery pipeline.

How would you prioritize which scanners to enable first in a greenfield pipeline?

Answer

1. Secrets (immediate high impact). 2. SCA on dependencies. 3. SAST on application code. 4. IaC if Terraform/K8s manifests ship. 5. Container scan before deploy. Tune severity thresholds before blocking merges.
