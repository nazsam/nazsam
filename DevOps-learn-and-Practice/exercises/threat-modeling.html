Threat Modeling

What is STRIDE?

Answer

Microsoft mnemonic for threats: Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, Elevation of Privilege — applied per component/data flow.

What is a data flow diagram (DFD) in threat modeling?

Answer

Visual map of processes, data stores, external entities, and trust boundaries — foundation for identifying where threats apply.

What is an attack tree?

Answer

Hierarchical decomposition of goals into sub-goals and steps an attacker might take — useful for prioritizing controls and red-team scenarios.

How does threat modeling fit shift-left?

Answer

Run during design before code hardens — cheapest time to add auth, encryption, logging, and segmentation. Revisit on major architecture changes.

What is the difference between a threat and a vulnerability?

Answer

Threat = potential adversary/event. Vulnerability = weakness that could be exploited. Risk combines threat, vulnerability, and impact.

What is trust boundary crossing?

Answer

Where data crosses from a lower-trust to higher-trust zone (or vice versa) — internet→app, app→database, tenant→tenant. Primary focus for controls.

How can AI assist threat modeling responsibly?

Answer

Suggest overlooked abuse cases, draft STRIDE tables, summarize architecture docs — human validates assumptions, never treats AI output as final risk acceptance.

What is PASTA?

Answer

Process for Attack Simulation and Threat Analysis — risk-centric, seven-stage methodology aligning business impact with technical threats.

When is a threat model "done"?

Answer

Never permanently — living artifact updated with new features, integrations, and incident lessons. Version and review on major releases.

What mitigations typically address spoofing?

Answer

Strong authentication (MFA, mTLS, token validation), anti-phishing, certificate pinning, and identity federation with proper audience checks.
