Containers & Supply Chain

Why run containers as non-root?

Answer

Limits privilege escalation and host impact if the container is compromised — align with CIS Docker/K8s benchmarks.

What is a minimal/base image strategy?

Answer

Use distroless or slim images — smaller attack surface, fewer CVEs, faster scans. Rebuild regularly for patched upstream layers.

What does Cosign provide?

Answer

Container signing and verification — sign images in CI, verify at admission/deploy time for supply-chain integrity (pairs with SBOM tools like Syft).

What is dependency confusion?

Answer

Attacker publishes malicious package with same name as internal private package — build tools pull public version. Mitigate with scoped registries, lockfiles, and namespace controls.

How do read-only root filesystems help?

Answer

Prevents runtime file drops, malware persistence, and config tampering inside the container — common in hardened K8s pod specs.

What capabilities should you drop in Linux containers?

Answer

Drop ALL and add only required caps (often none). Never need CAP_SYS_ADMIN for typical web apps.

What is an image digest vs a tag?

Answer

Tag = mutable pointer (latest). Digest = immutable content hash (sha256:...). Deploy by digest for reproducibility and tamper detection.

What is Trivy used for in container pipelines?

Answer

Scan OS packages and app dependencies for CVEs, misconfigs in Dockerfiles/K8s manifests, and secrets — common in CI gates.

Explain the build-time vs run-time security split for containers.

Answer

Build-time: base image choice, Dockerfile lint, SCA, signing. Run-time: admission policy, seccomp/AppArmor, network policy, Falco/eBPF monitoring.

What is a software provenance attestation?

Answer

Signed metadata linking an artifact to its source repo, commit, builder, and dependencies — SLSA Level 2+ goal for supply-chain trust.
